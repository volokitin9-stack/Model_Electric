# Агент поставок (WeChat → проект → Telegram)

Агент **только читает** переписку с поставщиками в WeChat, определяет изменение статуса
переговоров/поставки по каждой позиции, записывает его в проект и пишет в Telegram:
- 🔄 изменился статус (например: «оплачено, но разъёмы ещё не отгружены»);
- ⏰ поставщик не отвечает N дней;
- 📩 поставщик ждёт нашего ответа;
- 💳 счёт получен, но не оплачен;
- 🚨 оплачено, но не отгружено;
- ⚠️ нет в наличии / задержка;
- 🚚 долго в пути;
- 💤 нет движения по заказу.

Напоминание по одной и той же проблеме повторяется не чаще, чем раз в `remind_repeat_days` дней.

## Файлы

| Файл | Что это |
|---|---|
| `suppliers.csv` | Поставщики: `supplier_id`, имя, ники в WeChat (`wechat_names`, через `;`), какие P/N поставляет |
| `orders.csv` | Позиции заказов (одна строка = заказ + P/N). Оплата и отгрузка ведутся **раздельно** по каждой позиции |
| `events.csv` | История: каждое распознанное событие с цитатой из переписки |
| `STATUS.md` | Сводная таблица статусов (генерируется) |
| `config.json` | Пороги в днях для напоминаний, ваши имена в выгрузке (`me_names`) |
| `notifications.md` | Куда пишутся уведомления, если Telegram не настроен |
| `../wechat_inbox/` | Сюда кладутся новые выгрузки переписки; после разбора переносятся в `processed/` |

Статусы оплаты: `quoted` → `invoiced` → `paid` (мы оплатили) → `confirmed` (поставщик подтвердил).
Статусы отгрузки: `production` → `ready` → `partial` → `shipped` → `delivered`, плюс `stock_out`, `delayed`.

## Как передать переписку

WeChat не даёт API для чтения личных чатов, поэтому переписка попадает в проект выгрузкой:

1. **Копирование из WeChat для ПК**: выделить сообщения → скопировать → сохранить как
   `wechat_inbox/<supplier_id>__<любое>.txt` (например `KLS__2026-11-03.txt`).
   Поддерживаются форматы «`Имя 2026/11/1 10:23` + текст на следующих строках» и
   «`2026-11-01 10:23 Имя: текст`».
2. **CSV из MemoTrace / WeChatMsg** (экспорт истории чата) — колонки `StrTime`, `IsSender`,
   `StrContent`, `NickName`/`Remark` распознаются автоматически.

Повторно выгруженные сообщения не дублируются (по хешу). Поставщик определяется по префиксу
файла или по нику отправителя из `wechat_names`.

## Запуск

```bash
python3 tools/supply_agent.py run                 # разобрать inbox + проверить зависания + отправить
python3 tools/supply_agent.py check               # только напоминания
python3 tools/supply_agent.py set PO-2026-014 L-KLS1-4.20-FT ship_status=delivered   # ручная правка
python3 tools/supply_agent.py tg-test             # проверка Telegram
```

Telegram: переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

## Пример

`examples/` — поставщик KLS, заказ из двух позиций: корпуса 2X08 оплачены, но в производстве,
контакты FT отгружены с треком. Проверка:

```bash
mkdir -p /tmp/demo/wechat_inbox/processed && cp -r supply /tmp/demo/ \
 && cp supply/examples/{suppliers,orders}.csv /tmp/demo/supply/ \
 && cp supply/examples/KLS__chat.txt /tmp/demo/wechat_inbox/ \
 && python3 tools/supply_agent.py run --root /tmp/demo --now "2026-11-03 12:00" --dry-run
```
