# Local Import Agent

Небольшой Node.js-скрипт, который читает прайс-листы поставщиков из
папки на вашем компьютере и загружает их в API «Модельной электрики» —
тем же путём, каким это делает загрузка файла в браузере
(`POST /api/imports/preview`).

## Зачем это отдельный скрипт

Сервер «Модельной электрики» обычно работает в облаке или на другом
компьютере и не имеет доступа к диску `C:\` пользователя. Обычное
веб-приложение в браузере тоже не может само читать произвольные файлы
с диска. Поэтому чтение локальной папки выполняет отдельный скрипт,
который вы запускаете сами на своём компьютере — он отправляет файлы на
сервер по сети, а не наоборот.

**Важная честная оговорка**: этот скрипт написан и несколько раз
проверен против локальной тестовой папки в среде разработки, но
**не был опробован на реальном Windows-компьютере пользователя** —
у среды, где он написан, нет доступа к такому компьютеру. Логика (обход
папок, сопоставление кода поставщика, загрузка файла, вызов API)
одинакова для Linux/macOS/Windows — Node.js кросс-платформенный, —
но сначала стоит один раз проверить его на небольшой тестовой папке
перед тем, как полагаться на него регулярно.

## Установка

1. Нужен [Node.js](https://nodejs.org/) 18 или новее (есть `node -v`?).
2. Скопируйте `config.example.json` в `config.json` рядом с `agent.js`.
3. Укажите в `config.json`:
   - `serverUrl` — адрес вашего сервера (например, `http://localhost:4000`).
   - `rootFolder` — папка с подпапками поставщиков, например
     `C:\ModelElectric\Suppliers`. Путь не зашит в коде — именно
     поэтому его нужно указать здесь.
   - `agentToken` — если на сервере задана переменная окружения
     `AGENT_API_TOKEN`, впишите сюда то же значение.

## Структура папки

```
C:\ModelElectric\Suppliers\
  SUP01\
    price.xlsx
    cross.xlsx
  SUP02\
    price.csv
  ...
```

Имя подпапки должно совпадать с **кодом** поставщика в системе
(поле «Код поставщика» на странице `/suppliers`). Файлы внутри —
XLSX, XLS или CSV, в любом количестве.

Перед первым запуском для каждого поставщика нужно один раз настроить
**шаблон импорта** (сопоставление колонок) — это делается в веб-
интерфейсе на странице поставщика, не в агенте: агент сам не
придумывает, какая колонка — это наш артикул, а какая — цена
(нечёткое угадывание структуры файла — не то, что должно сохраняться
автоматически, см. ТЗ §18).

## Запуск

```bash
cd apps/local-import-agent
node agent.js
```

Без флагов агент только показывает предпросмотр изменений по каждому
файлу (сколько новых кроссировок, изменений цены, неизвестных
артикулов и т.д.) — **ничего в базе не меняет**. Подтвердить изменения
можно двумя способами:

- Зайти на страницу поставщика в вебе, вкладку «История обновлений», и
  подтвердить нужный пакет там (видно то же самое, что показал агент).
- Или запустить агент с `--confirm` — тогда он сразу подтверждает все
  успешно разобранные пакеты:
  ```bash
  node agent.js --confirm
  ```

Другие флаги:
- `--supplier SUP01` — обработать только одного поставщика.
- `--config путь/к/файлу.json` — использовать другой файл конфигурации.

## Безопасность (ТЗ §17.3)

- Агент читает файлы только внутри указанной `rootFolder` — никаких
  произвольных путей.
- Содержимое файлов никогда не исполняется — ни как код, ни как
  макросы; агент только читает байты и пересылает их серверу, разбор
  делает та же библиотека (`xlsx`), что и для загрузки через браузер.
- Файлы больше 15 МБ и не с расширениями `.xlsx/.xls/.csv`
  пропускаются.
- Если на сервере задан `AGENT_API_TOKEN`, агент посылает его заголовком
  `x-agent-token` — без него запросы с этим заголовком отклоняются.
  Это простой разделяемый секрет, а не полноценная система
  пользователей (её в приложении пока нет вообще, см. README в корне
  репозитория).
- Агент не запускает непрерывное сканирование папок в фоне — только по
  явному запуску (`node agent.js`), как и требует ТЗ.
